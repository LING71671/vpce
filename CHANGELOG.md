# Changelog

## 1.0.0 — 2026-10-22

First public release.

**Two channels into a local Visual Paradigm installation**

- XML channel: `ExportXML` / `ImportXML` / `ExportDiagramImage`, no plugin
  required. Reads the full model, writes elements, renders diagrams.
- Open API channel: a small Java plugin (`com.vpce.bridge`) loaded by
  `com.vp.cmd.Plugin`, exposing a reflective statement interpreter. Needed for
  new diagrams, connectors and anything outside the XML schema.

**`vpce draw` — diagram from a JSON spec**

- One spec covers every diagram type the installed build supports: nodes of
  any of the 1455 model element types, edges of any relationship type.
- Layout profiles per diagram type (`layered`, `grid`, `usecase`, `radial`,
  `explicit`), overridable from the spec.
- Writes through the Open API, verifies by re-exporting through the XML
  channel, then renders a PNG.

**Interfaces**

- CLI: 15 commands (`status`, `summary`, `diagrams`, `elements`, `draw`,
  `images`, `export-xml`, `import`, `create-class`, `upgrade`, `api`,
  `introspect`, `search`, `bridge`, `mcp`).
- MCP: 14 tools over stdio, including `vp_draw` and the `vp_api` escape hatch.
- Python: `vpce.app.App` with `ProjectService` / `DrawService` / `ApiService`.

**Architecture**

- Five layers with one-way imports: transport → service → ports → adapters →
  core. `core` is pure and unit tested without Visual Paradigm.

**Measured coverage** (`COVERAGE.md`, generated by `tools/coverage.py`)

- Element types: 1455 / 1455 creatable (4 only through `createChild`).
- Diagram types: 31 / 106 creatable, 29 render a non-empty PNG; the remaining
  75 raise `UnsupportedOperationException: <type> is not supported` on this
  Community Edition build, and 2 are editor-style canvases that accept no
  model elements.
- Command classes: 11 / 28 executable, 17 gated by the edition.

**Known limitations**

- One JVM per call, 7–10 s; batch by combining work into one spec or script.
- A project open in the GUI cannot be written to (`Project file locked`).
- Connectors follow Visual Paradigm's default straight routing; waypoints are
  possible through `vpce api` but not exposed in the spec yet.
