# vpce — drive Visual Paradigm from a JSON spec

Hand a JSON spec to the tool and it builds the model, creates the diagram,
draws the relationships, saves the project and renders a PNG — inside a real
Visual Paradigm installation, with no GUI and no clicks.

```
vpce draw examples/order-system.json --project demo.vpp --out png/
```

Result: five classes with attributes and operations, four associations, a
layered class diagram, and a rendered image.

Verified against **Visual Paradigm Community Edition 18.1 (build 20261011)**
on Windows 11 with the bundled Temurin JRE 11.0.16.1.

## 1. Two channels

| Channel | Mechanism | What it can do | Requires |
|---|---|---|---|
| **XML** | `ExportXML` / `ImportXML` / `ExportDiagramImage` | read the full model, write elements, render diagrams | nothing |
| **Open API** | the `com.vpce.bridge` plugin, loaded by `com.vp.cmd.Plugin` | create diagrams, any element type, connectors, geometry, save, call anything under `com.vp.plugin.*` | `vpce bridge --install` once |

`draw` uses the Open API channel; reads and renders go through XML. The two
verify each other: after a write, the project is re-exported and checked
through the other code path.

## 2. Install

```bash
python java/bridge/build.py        # compile the plugin with the JDK bundled with VP
python -m vpce bridge --install    # copy to %APPDATA%\VisualParadigm\plugins\
python -m vpce status              # confirm the installation is found
```

The installation directory is resolved from `--vp-home`, then `VPCE_HOME` /
`VP_HOME`, then the registry entry the installer writes, then a scan of the
usual install roots.

## 3. Drawing is a spec

```json
{
  "diagram": "ClassDiagram",
  "name": "Order System",
  "nodes": [
    {"id": "customer", "type": "Class", "name": "Customer",
     "attributes": ["id:long", "email:string"], "operations": ["placeOrder"]},
    {"id": "order", "type": "Class", "name": "Order",
     "attributes": ["total:double"]}
  ],
  "edges": [
    {"from": "customer", "to": "order", "type": "Association", "name": "places"}
  ],
  "layout": {"mode": "layered"}
}
```

- `diagram` — any diagram type. The build supports 31 of the 106 constants
  (see [coverage](COVERAGE.md)); 75 raise `is not supported`.
- `nodes[].type` — any model element type. The factory accepts 1455 names,
  listed in `vpce/core/model_types.json`; a wrong name fails with a suggestion
  instead of an empty diagram.
- `edges[].type` — `Association`, `Generalization`, `Dependency`, and the rest
  of the relationship types.
- `layout.mode` — `layered` (default), `grid`, `usecase`, `radial`, `explicit`.
  Left out, the diagram type's own profile decides.

## 4. CLI

```
vpce status [--probe]                 installation info and edition-gate probe
vpce summary <project>                element counts and diagram list
vpce diagrams <project> [--text]      diagrams
vpce elements <project> --text        model elements
vpce draw <spec.json> --project P     draw (--plan: layout only, --script: show statements)
vpce images <project> --out DIR       render diagrams
vpce export-xml <project> --out DIR   export the model
vpce import <project> --file X.xml    merge an XML document
vpce create-class <project> NAME      create a class through the XML channel
vpce upgrade <project>                upgrade an older project file
vpce api <project> '$expr'            run Open API statements
vpce introspect <project> IDiagram    list methods and constants of an API class
vpce search <project> Diagram         find API classes by name
vpce bridge [--install|--uninstall]   manage the plugin
vpce mcp                              start the MCP server (--read-only hides writes)
```

`--plan` is the self-check: it lays out the spec and returns the statements
without touching the project.

## 5. MCP

```json
{
  "mcpServers": {
    "vpce": {
      "command": "python",
      "args": ["-m", "vpce", "mcp"],
      "cwd": "/path/to/vpce",
      "env": { "VPCE_HOME": "/path/to/Visual Paradigm" }
    }
  }
}
```

14 tools: `vp_draw`, `vp_project_summary`, `vp_model_list`, `vp_diagram_list`,
`vp_export_xml`, `vp_export_images`, `vp_create_class`, `vp_import_xml`,
`vp_upgrade`, `vp_status`, `vp_api_search`, `vp_api_introspect`,
`vp_bridge_status`, and `vp_api` as the escape hatch.

## 7. Limits

- One JVM per call (7–10 s); combine work into one spec or script.
- A project open in the GUI cannot be written to.
- Exported images carry the Community Edition watermark.
- Connectors use Visual Paradigm's default straight routing.
- `ExportXMI` and `InstantReverse` are gated in the Community Edition.
